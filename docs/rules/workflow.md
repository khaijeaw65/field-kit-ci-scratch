# Workflow — field-kit CI scratch

> Generated by field-kit 0.1.0 on 2026-11-15. Owned by Field — protected file (`agent-boundaries.md`).
> Process manual. Skills read the section they need. The Field Guard and hard rules live in `AGENTS.md` (always loaded).

## 1. People, Roles, Sessions

- **Field — KJ (`kj`):** decision authority, Owner / executor, final merge approver.

A **role is a session**, not a person. One person may run every role, switching tools; a role never audits its own work.

| Session | Typical tool | Writes |
|---|---|---|
| Planning | Cowork | Drafts in the main checkout (uncommitted): briefs, feature specs, defect files, DRs, FRD |
| Implementation | Claude Code, Cursor, Codex — host tools only (git runs inside the worktree; a VM cannot) | Code + tests + handoff inside the brief's worktree; all brief commits and pushes |
| Audit | Cowork (or Codex when Field assigns it) | Audit report only, uncommitted in the brief's worktree |
| PR review | a host tool with `gh` | Merge, worktree cleanup |
| Autopilot | executor | Its own `auto/…` worktree and `docs/PLAN.md` |

A person who writes code by hand follows the Implementation steps exactly; AI reviews the work against the rule files.

## 2. Documents

```text
docs/
  README.md                    # docs map — start here
  FRD.md                       # product overview: scope + feature list → links to features/<f>/
  features/<f>/                # deep spec, created when a feature is picked up (≥ 2 briefs or shared contract)
    requirements.md · design.md · ui.md (screens only)
  features/INVARIANTS.md       # rules that must never break; read when planning or when a diff touches them
  briefs/BRIEF-###-<slug>.md   # one executable slice (frozen at merge)
  defects/DEFECT-###-<slug>.md # every defect: log, root cause, "caught at", fix link
  decisions/DR-###-<slug>.md   # one decision
  handoffs/BRIEF-###.md        # executor → auditor evidence
  audits/BRIEF-###.md          # independent review of work commit S
.field-kit/state/<id>-<kind>.md  # local session pointer (gitignored)
.worktrees/BRIEF-###/            # one worktree per brief (gitignored)
```

- **Specs** (`FRD`, `features/`) are Field-owned. Every requirement cites a **Source** (who, how, date). A brief or DR that changes a contract, flow or code map updates `design.md` in the same PR.
- **State** is a local pointer only (resume · active brief/branch/worktree · blockers · session checkpoint), never committed. Backlog, follow-ups, parked work and milestones live in the project's PM tool (or `docs/BACKLOG.md` when there is none); decisions live in DRs.
- **Screenshots** for run proofs go to `.field-kit/proof/` in the worktree (gitignored); the audit describes them in words. Never commit images of run proofs.
- **Docs-branch line** — docs no brief carries (standalone DR, logged-only defect, FRD, rules): one `docs/<topic>` branch per batch, PR by the host git tool, same day.

## 3. Flow

```text
/new-brief (triage) ─┬─ > 1 flow/surface or shared contract → /new-feature → slices → /new-brief each
                     └─ brief Draft → Dry Run → Field "Ready"            (main checkout, uncommitted)
execute ── worktree + seed commit → Step 0: e2e red = lock → build steps (1 step = 1 commit)
        ── gates + run proof → handoff commit = S → push
audit   ── PASS ─────────────→ ship: commit audit + handoff = H → push → PR → pr-review → merge
        └─ CHANGES REQUIRED → fix → new S → re-audit
```

### 3.1 Triage and size (in `/new-brief`)
- **Scope:** one outcome Field can check (one user flow) on one surface (backend or web or mobile). More → `/new-feature` or split.
- **Complexity flags:** new pattern/lib · concurrency / transaction / idempotency · money / auth / personal data · external integration · migration touching existing rows · open unknowns. **Hard flags:** concurrency/transaction · money/auth/personal data · external integration · migration touching existing rows.
- 0–1 flag → normal brief. 2+ flags → split so each brief carries at most one hard flag, or Field records an accepted oversize. Flags tell the auditor where to look; they do not predict how many findings a brief gets.
- **Sections on** (brief header, fixed tokens): `e2e` (behaviour visible via API/UI) · `runproof` (runtime change) · `ui` (screens) · `guard` (schema/deps/contract) · `repro` (bug). The Dry Run covers only the rows of switched-on sections.

### 3.2 Planner Dry Run (before Ready, `path:line` evidence)
1. Existing schema / entities read now — only external/runtime facts stay *Assumed*.
2. Wiring trace of every existing file the executor will touch; protected files listed in the brief's unlock list.
3. Packages and peer versions verified in the manifest.
4. Gate scripts exist (or `BLOCKED until BRIEF-###`).
5. `e2e`: isolation config exists (own DB, Redis prefix, random port) **or** isolation is Build step 1.
6. Every *Depends on* brief merged to `main`; no code-map overlap with briefs in flight (scan `.worktrees/*` and `feat/BRIEF-*` branches).
7. `ui`: every token/component `ui.md` names exists, or the gap is a build step / DR.
8. Contract nullability matches DB nullability; no invented `?? ''` fallbacks.
9. `runproof`: the run proof is feasible — accounts, keys, callbacks, devices available — or narrowed in the brief now.

Executors never turn a Draft into Ready. Record approval in the brief changelog; bump the revision on content changes.

### 3.3 Implementation (in the brief's worktree)
1. **Seed:** `git worktree add --no-track .worktrees/BRIEF-### -b feat/BRIEF-###-<slug> origin/main` after `git fetch`; move the brief's own new files (brief, defect file, new feature folder) into it; apply tracked-file hunks (e.g. `INVARIANTS.md` rows) inside the worktree and restore the main-checkout copy; set the defect `Status: In progress · Fixed by: BRIEF-###`; copy `.env*` (never committed); install deps; commit `docs(BRIEF-###): Ready — Rev n`.
2. **Step 0:** verify executor-owned *Assumed* rows; write the e2e files from the brief's Acceptance test plan (mirror an existing green e2e); run → every new-behaviour case fails red on an assertion (cases already true are listed); commit **test files only** as `test(BRIEF-###): acceptance (red)` — the **lock** — and push it right away. The e2e runner config present at that commit is locked with it. Red output goes into the handoff. A locked file changed without the OK → `git revert` that commit (CI checks the net change since the lock); never rewrite branch history. A later change to a locked e2e file needs Field's OK and a commit with `Approved-by: Field (e2e-change)`.
3. **Build steps:** inside → out, unit tests per step, **1 step = 1 commit** `feat(BRIEF-###): <step>`. Large context → `/checkpoint`; a fresh session resumes from the last commit.
4. **Gates + run proof:** all brief gate commands green; run proof = stack up → migrations → health 200 → a real request on the changed path (UI: exercised on screen; defect: the repro replayed). Isolation: `COMPOSE_PROJECT_NAME=brief-###` and no fixed host ports, otherwise one stack at a time. Anything required not run → `BLOCKED`, ask Field.
5. **Handoff:** write `docs/handoffs/BRIEF-###.md`, commit `docs(BRIEF-###): handoff` = **S**, push. Then append `Work commit: <S>` and the CI run URL to the handoff (uncommitted — lands in H). `Next → in Cowork: audit BRIEF-###`.
6. **Fix round:** fix only `Must fix`; re-run gates + run proof; commit, push, append a fix round to the handoff; new S.
7. **Ship (after PASS):** commit the audit report unchanged + final handoff = **H**, push, open the PR. `Next → in <host git tool>: pr-review`.

Stage explicit paths only — never `git add -A` / `git commit -a`. No bookkeeping-only commits.

### 3.4 Concurrent briefs
Allowed when code maps do not overlap (checked at Ready). Before committing S, `git fetch && git merge origin/main` and reconcile shared files by hand; if `main` changes a shared file during the audit, merge it as a fix commit and ask for a compact re-audit.

### 3.5 Commits and pushes
| Who | Commits | Pushes |
|---|---|---|
| Planning / Audit sessions | none (files left uncommitted; docs-branch line for standalone docs) | none |
| Executor | seed · lock · 1 per build step · handoff (S) · each fix · ship (H) | after the lock, after S, after each fix, after H |
| Nobody | state files, commits whose only content is a SHA or PR link (the handoff's `Work commit` line rides in H), direct commits to `main` | `main` |

## 4. Identity, Commands, Session Loop

`onboard <id>` writes `{ "developer": "<id>" }` to the gitignored `.agent-local.json` and creates the local state file from `.field-kit/state/_TEMPLATE.md`. Explicit session input wins; never infer identity from Git author or tool account.

| Command | Section | What it does |
|---|---|---|
| `/new-brief` | 3.1–3.2 | Default entry: triage → Draft → Dry Run → Ready on Field's explicit OK. Routes to `/new-feature` when scope says so. |
| `/new-feature` | 2, 3.1 | Interview → `features/<f>/` (+ FRD link, INVARIANTS rows) → proposed slices. |
| `/new-defect` | 2 | Log + investigate: defect file with root cause and "caught at" → offer `/new-brief Type: Defect`. |
| `/new-dr` | AGENTS.md Guard | Pending DR with options, under-the-hood flow, recommendation. |
| `execute BRIEF-###` | 3.3 | Seed → Step 0 lock → build → gates → handoff (S). |
| `fix BRIEF-### (#…)` | 3.3 step 6 | Fix listed `Must fix` only. |
| `ship BRIEF-###` | 3.3 step 7 | Audit + handoff = H → PR. |
| `audit BRIEF-###` | 6 | Independent audit of S from the main checkout against the branch ref. |
| `/review` | 6 | Mid-coding diff check against rule IDs; no audit file. |
| `pr-review` / `approve merge BRIEF-###` | 7 | CI on H, S..H, authority, merge, worktree cleanup. |
| `/checkpoint` · `resume` | 1, 2 | Flush decisions to working files + local state; pick up with a 3-line header. |
| `/autopilot` | 4 | Unattended run in its own `auto/…` worktree from `docs/PLAN.md`; one PR. The one exception to the brief flow — personal / low-stakes work only. |
| `status BRIEF-###` | — | Read-only: brief, branch, PR, CI. |
| `handoff` | 3.3 | Stopping mid-brief: WIP commit `chore(BRIEF-###): wip — <step>` + push on the brief branch (no state, no PR). |

**Cross-tool rule:** at S the executor writes `Next → in Cowork: audit BRIEF-###`; the auditor answers `Next → in <Executor>: fix …` or `ship …`. A session asked to audit work it implemented, fixed or paired on refuses and names the assigned auditor.

**No manual tasks for Field:** hand work to an executor as a command or a docs-branch line — never as shell steps for Field. Protected edits: the agent shows the exact diff, Field OKs, the agent writes.

## 6. Quality Gates, Grounding, Audit

| Where | Checks |
|---|---|
| pre-commit (seconds) | project linter on staged files; conventional commit message (scope optional; `Revert "` passes) |
| pre-push (≤ 1–2 min) | typecheck + affected unit tests — blocking; skipped only when every pushed commit touches `docs/**`; `--no-verify` must be disclosed in the handoff |
| CI = G2 (check `ci`) | affected lint / typecheck / test · e2e with services · OpenAPI check (backend) · **e2e lock** (`scripts/field-kit/check-lock.sh`) |
| Audit = G3 | ACs · logic / race / security (focus from `Flags:`) · e2e covers the test plan · net post-lock e2e diff · protected paths covered · every `Approved-by` trailer matches the §9 unlock list or an *Owner approvals* row in the handoff · triage matches the diff · `ui.md` rows · rule IDs tagged `[review]` |

- **G1:** the brief's gate commands + run proof (Section 3.3 step 4).
- **G2:** check `ci` green on the PR head H.
- **G3:** assigned audit PASS, zero open `Must fix`, Field review. `Suggest` findings never block.


### Grounding rules
1. Read the brief, linked specs, `INVARIANTS.md`, DRs and contracts before writing behaviour.
2. Preserve approved DTO fields, enums, payloads. Never invent business fields, error codes or fallbacks.
3. Missing business / security / payment / personal-data behaviour is a blocker or DR, not a TODO.
4. Respect module boundaries and the rule files.
5. Compare brief ↔ design ↔ contract ↔ code ↔ tests before review; the auditor reads sources and diff independently.
6. Report exact commands, environment, work SHA S, exits, counts, limits. Never log secrets or personal data.

## 7. Branching, Approval, Completion

Main is the only long-lived branch. Branch `feat/BRIEF-###-<slug>` (or `fix/…`), commits `<type>(BRIEF-###): <message>`, PR title `BRIEF-###: <title>`.

**S..H integrity:** the audit reviews S; the report lands at H. Before merge, `git diff --name-only S..H` must contain only `docs/audits/BRIEF-###.md` and `docs/handoffs/BRIEF-###.md`. Anything else → re-audit.

**Merge authority:** Field's own PRs are pre-approved once audit PASS, S..H is evidence-only and `ci` is green on H. Other members' PRs need Field's explicit `approve merge BRIEF-###` for the exact H. `pr-review` checks authority **before** any approval; when the PR author is the current GitHub user it skips `gh pr review --approve` (GitHub refuses self-approval).

**Merge method:** merge commits only (`gh pr merge --merge --match-head-commit <H>`); never squash or rebase. `--admin` only where `ops/github/README.md` allows it (team profile, CI green on H). After merge: `git worktree remove .worktrees/BRIEF-###`, delete the branch, `git pull --ff-only` in the main checkout. Merged PR = Done.

**Deploy:** merging never deploys. Deploys come from release tags only Field creates, or a manual dispatch.

## 8. Why
Specs, briefs, locked acceptance tests, DRs, handoffs, audits and PRs are durable evidence of planning, review and delivery — enough for someone else to pick the work up from the repo alone.
